# Casual Studio 제품 설계 (#749)

**작은 부품을 처음부터 만들거나, 기존 설계를 내 치수에 맞춰 다시 쓴다.** 결과를 캔버스에서 확인하고, 피처를 다시 편집할 수 있는 CAD 파일로 가져간다.

첫 버전의 대상은 브래킷·장착판·작은 케이스를 만드는 사람이다. 예를 들어 “장비에 새 구멍을 뚫지 않고 케이블 가이드를 옆에 달기”는 예제에서 빠르게 시작할 수 있다. “내 치수로 구멍 세 개가 있는 판을 반복해서 만들기”는 코드에서 새로 시작할 수 있다. 두 작업을 같은 예제 수정으로 취급하지 않는다.

| 제품 | 맡는 일 |
| --- | --- |
| **Casual Studio** | 작은 파라메트릭 모델을 코드로 만들거나, 만들어진 모델을 필요한 치수만 수정한다. |
| **CAD Studio** | 처음부터 정밀하게 설계하고, 임의 스케치·피처·조립 이력을 편집한다. |
| **Viewer** | 모델을 변경하지 않고 검토한다. |

## 첫 화면과 작업 공간

첫 화면의 동등한 선택지 두 개는 **예제로 시작**과 **코드로 만들기**다. **파일 열기**는 별도 경로로 항상 보인다.

| 시작 방법 | 첫 화면 이후 실제로 하는 일 |
| --- | --- |
| 예제로 시작 | 결과 이미지, 용도, 공개 치수가 보이는 예제를 선택한다. 예제 목록이 닫힌 뒤 캔버스에서 A 구멍을 누르고 지름을 바꾼다. 코드를 열지 않아도 저장할 수 있다. |
| 코드로 만들기 | 코드가 열린 **빈 프로젝트**에서 시작한다. 캔버스는 첫 미리보기 전에는 비어 있다. “샘플 코드 삽입”은 선택 사항이며, 아무 기존 판에도 연결하지 않는다. “코드 붙여넣기 → 미리보기”만으로 새 모델을 만들 수 있어야 한다. |
| 파일 열기 | 레시피를 열면 코드와 공개 치수를 복원한다. 지원되는 기존 `.bcad`는 원본 피처 이력을 유지하며 허용 치수만 편집한다. 지원 여부를 먼저 판단하고, 열 수 없으면 기존 편집을 그대로 두고 CAD Studio를 안내한다. |

편집 화면의 기본은 작업 이름, 목적 한 줄, **캔버스**다. 부품·피처·치수 중에서 선택한 대상의 옵션만 표시한다. 데스크톱에서는 코드 패널이 왼쪽에 열리고, 좁은 화면에서는 캔버스 아래에 둔다. 새 코드 프로젝트에서 패널이 기본으로 열리지만, 미리보기 후 접어도 캔버스에서 공개 치수를 고칠 수 있다. 캔버스에서 구멍 이름과 실제 지름을 함께 표시한다. 선택하면 데스크톱에서는 모델 옆, 좁은 화면에서는 모델 바로 아래에 해당 치수만 연다. 적용 전에는 입력창 대신 기존과 후보 수치·적용·취소를 표시한다. 피처 트리·채팅·전체 속성표는 상시 표시하지 않는다.

```text
시작:  [예제로 시작]    [코드로 만들기]    [파일 열기]

편집:  문서 이름                          [코드] [Undo] [저장]
       ┌ 코드 (열었을 때만) ┬ 캔버스                         ┐
       │ 원문 + 줄 오류      │ 모델 → 선택한 대상 → 관련 치수  │
       └ [미리보기]          ┴ 변경 전 / 변경 후  [취소] [적용]┘
```

## 코드는 모델 전체를 정의할 수 있어야 한다

첫 기능은 범위를 좁히되 빈 문서에서 닫힌 판 하나와 0개 이상의 지름·위치가 다른 관통 구멍을 만들 수 있어야 한다. 지금의 `holeA.diameter = 8`은 기존 판에 값 하나를 넣는 실험이다. 아래는 첫 레시피 빌드에서 바로 쓸 수 있는 문법 예시다. 레시피 작업 공간에서는 구멍 지름에 연결된 선언을 캔버스에서 수정할 수 있다. 케이블 가이드 예제도 같은 편집기를 쓰며 코드는 처음에 접혀 있다.

```text
recipe 1
units mm

param plateWidth = 60
param guideDia = 6

plate base width=plateWidth depth=40 thickness=5
hole guide in=base at=(15, 20) diameter=guideDia
hole mount in=base at=(45, 20) diameter=6
output base
```

- `plate`는 기본 판, `hole`은 명시한 판을 가공하는 순서 있는 피처다. `output base`가 가리키는 것은 해당 판의 모든 가공이 끝난 결과다.
- 코드에서 `param`으로 선언한 값만 캔버스에 노출한다. 가이드 홀을 클릭해 6→8로 바꾸면 코드의 `guideDia` 선언만 수정한다. 한 선언을 여러 곳에서 쓰면 영향을 받는 피처를 먼저 표시한다. 이 예제에서 `mount`는 고정 지름이며, 코드에서 직접 변경하거나 별도 파라미터로 공개할 수 있다.
- 식에 묶인 치수에 임의의 숫자를 덮어쓰지 않는다. 원본 파라미터를 보여주거나 해당 코드 줄로 이동시킨다. 원문의 주석, 순서, 다른 선언은 유지한다.
- 문법 1단계는 단위, 이름, 숫자 리터럴, 명시적 파라미터 참조 및 허용된 CAD 연산만 받는다. JS 실행, 네트워크·파일 접근, 외부 import는 하지 않는다. 첫 구현은 8,192자, 이름 8자, 관통 홀 8개, 양의 치수 0.01~10,000 mm로 제한한다. 중복 이름·잘못된 참조·겹침·퇴화 형상은 줄과 이유를 표시한다.

## 원본, 미리보기, 저장

동일한 작업 공간을 쓰되 파일마다 편집 원본이 하나다.

| 문서 종류 | 편집 원본 | 보존과 전달 |
| --- | --- | --- |
| 레시피 및 코드로 만든 예제 | 버전이 명시된 텍스트 레시피 | **레시피 저장**은 실행 가능한 원문과 공개 파라미터를 보존한다. **CAD 파일 내보내기**는 현재 사용 가능한 native 스케치·돌출·홀 피처를 가진 `.bcad`를 만든다. |
| 열어 본 기존 CAD 파일 | 가져온 `StudioDoc` | 지원된 치수만 변경해 `.bcad`로 저장한다. 일반 `.bcad`에서 원본 레시피를 추정하거나 다른 앱에서 저장한 내용을 원래 레시피에 덮어쓰지 않는다. |

현행 `.bcad`에는 숫자와 이름 있는 단일 파라미터 참조를 담을 수 있다. 모든 레시피 식을 그대로 재현한다고 약속하지 않는다. CAD로 표현 가능한 참조는 가능한 한 native로 보존하고, 값으로만 내보낸 관계는 저장 전에 알려준다. 원문이 필요한 경우 레시피를 다시 연다. 레시피 원문을 담기 위해 `.bcad` 형식을 바꾸지 않는다.

편집 흐름은 한 가지다. **입력 → 형상과 영향 범위 검증 → 미리보기 → 적용.** 코드와 캔버스 모두 같은 경로를 통과한다.

- 코드까지 포함한 초안은 적용 전까지 커밋된 모델과 분리한다. 오류가 나면 마지막 유효 형상을 “마지막 적용 모델”로 남기고, 오류 상태를 새 결과처럼 보여주거나 저장하지 않는다. 이전 계산이 늦게 도착해 최신 입력을 덮을 수 없다.
- 미리보기는 바뀐 곳과 이유를 보여준다. 입증한 고정값만 표시한다. 적용 한 번은 원문·파라미터·모델을 같이 되돌리는 Undo 한 번이다.
- 피처 선택 및 코드 연결에는 안정적인 소유 ID를 쓴다. 화면 좌표나 피처 순서로 추정하지 않는다. 삭제된 대상은 선택을 비우고 모호한 대상은 편집하지 않는다.
- 문서 교체 시 적용하지 않은 초안과, 적용됐지만 현재 편집 원본으로 아직 저장되지 않은 변경을 구분한다. 레시피 프로젝트에서 CAD 내보내기는 레시피 저장으로 간주하지 않는다.

## 기술 경계와 출시 기준

Casual은 별도 앱과 셸을 유지한다. 컴파일·검증은 UI와 분리하고, 기존 native 문서·형상 평가·`.bcad` 저장을 사용한다. 검증은 레시피 → native 피처 → 평가된 형상까지 수행한다. 메시나 SVG는 표시용이다.

사용성 검증은 먼저 두 가지로 나눈다. (1) 예제 사용자는 사전 설명 없이 30초 안에 맞는 예제를 고르고 A만 바꿔 저장한다. 30초는 예제를 고르는 목표이며, 아직 측정하지 않았다. (2) 코드 사용자는 빈 화면에서 샘플 없이 자기 코드나 붙여넣은 코드로 모델을 만든다. 만든 모델의 주요 치수가 입력과 실제 형상에서 일치하고, 레시피를 다시 열어 이어서 수정할 수 있어야 한다. 두 흐름을 실제 Chrome에서 확인하고, 내보낸 파일은 CAD Studio에서 다시 편집한다.

이 단계는 범용 스케치·채팅 생성·임의 프로그래밍·범용 어셈블리 솔버·제조 검증을 포함하지 않는다. 다음 순서와 각 단계의 검증 기준은 [로드맵](ROADMAP.md)에서 관리한다.
