# D1984 — Recover one retired edge of a terminal Constant Fillet

P1 rows 15 and 16, [#20](https://github.com/barocss/cad/issues/20). Covers signed, terminal Constant Fillets with two or three distinct original unmerged straight edges. When the best-alike edge has a different identity, the ordinary Open verifier now reports a pending choice instead of substituting its name. The existing confirmation path checks the result before accepting it. The unchanged reference keeps its authored name and signature. No change to variable, fractional, curved or merged references, the agent edit policy, or the file schema.

- **Previous Chrome and Model:** the verifier marked the nearby edge as an automatic substitution, but Studio refused the file rather than applying the unmatched feature or offering recovery. The previously open model stayed unchanged.
- **Same-owner control:** narrowing the original 80 × 40 mm rectangle to 80 × 38 mm without replacing a side ID lets the existing Fillet follow, even with the original saved signatures. Retiring that side ID while keeping the geometry the same produces exactly one pending choice. No automatic reattachment occurs.
- **Current Chrome:** the file opens with the original two references retained and the Fillet held. The unrounded 80 × 38 × 10 mm stock is a valid 30,400 mm³ solid. Candidate preview does not change the document or Undo/Redo. Explicit confirmation replaces only the retired reference; the two native R2 cylindrical faces have axes at (−18, −16) and (58, 18) mm. Independent volume is 30,400 − 20(4 − π) mm³. Undo restores the held reference; Redo, native Save and fresh Open preserve the explicit result. Four captured desktop states, zero errors, and 1,233 unchanged frozen source paths.
- **Focused checks:** 42 reference tests, 2 signed half-ring controls and 15 Studio replacement tests. The existing three-held-edge Chrome driver also passes, including group replacement, native Save and fresh Open. Model type-check, scoped lint, driver syntax and diff checks.
